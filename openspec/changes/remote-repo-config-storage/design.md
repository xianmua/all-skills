## Context

`all-skills` 需要从多个 git 仓库（origins）获取 skill 包。用户通过 `add-origin` 命令添加新的仓库来源，这些配置需要持久化存储到本地文件。

当前实现已经将配置存储在 `~/.all-skills/config.toml`，但需要确保：
1. 配置文件路径跨平台兼容（Windows/macOS/Linux）
2. 配置读写操作原子性（避免写入时出错导致配置损坏）
3. 配置变更能被正确检测和保存

## Goals / Non-Goals

**Goals:**
- 配置持久化到 `~/.all-skills/config.toml`
- 支持配置的增删改查操作
- 提供配置验证机制
- 支持默认配置自动生成

**Non-Goals:**
- 不实现配置的加密存储
- 不实现配置的云端同步
- 不实现多用户/多实例配置隔离

## Decisions

### 1.配置文件路径

**选择**: 使用 `dirs` crate 获取用户 home 目录
**原因**:
- `dirs` crate 提供跨平台统一的目录获取接口
- `~/.all-skills/` 是 Linux/macOS 的标准约定，Windows 下也兼容
- 避免使用环境变量（如 `$HOME`）可能带来的兼容性问题

### 2. 配置文件格式

**选择**: TOML 格式
**原因**:
- TOML 格式人类可读，便于调试和手动编辑
- Rust 生态有成熟的 `toml` crate 支持
- 与项目现有的配置格式保持一致

### 3. 配置读写策略

**选择**: 读取时全量加载，写入时全量覆盖
**原因**:
-简化实现复杂度
- 避免部分写入导致配置损坏
- 文件较小，全量读写性能可接受

## Risks / Trade-offs

- **[风险]** 配置文件被手动编辑导致格式错误
  - **缓解**: 添加配置验证逻辑，读取失败时给出友好的错误提示

- **[风险]** 并发写入导致配置丢失
  - **缓解**: 当前为单用户工具，可接受。未来可考虑加文件锁

- **[权衡]** 默认配置是否应该包含预设的 origins
  - **决策**: `with_defaults()` 提供一个默认的 GitLab 源，用户可自行修改或删除
